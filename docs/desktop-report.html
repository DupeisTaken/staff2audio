Architecture and tradeoffs

The existing deterministic OpenCV/PyMuPDF recognizer and Web Audio frontend remain the core. PyInstaller freezes them into an OS-specific executable. Keeping the system browser avoids shipping another browser engine or introducing a native webview runtime. The tradeoffs are larger downloads, a temporary extraction step at launch and a console-owned service lifetime.

The launcher retains a loopback socket through startup, passes that socket to Uvicorn, and observes its own server readiness before opening the browser. Assets resolve from module locations inside the bundle. Frozen Linux browser launches restore the system library path. Explicit ports remain explicit; the default can fall back automatically.

Release mechanics

GitHub Actions builds natively with Python 3.12 and constrained dependencies. At most two matrix jobs run at once. Each native executable must pass both packaged smoke scenarios before it is archived. Archives preserve executable permissions and include license copies, a quickstart and SHA-256 sidecars. A v* tag publishes a release only after all four builds, JavaScript regressions and cross-platform archive checksum verification pass; the built-in GitHub token is sufficient for unsigned publication. This change does not create a release tag.

Remaining limits

  • Unsigned executables: Windows SmartScreen/macOS Gatekeeper approval can be required. Managed devices may require signing. Apple notarization and platform signing need maintainer credentials.
  • macOS ships a terminal executable, not an installable .app or DMG. Keep the console open and use Ctrl+C to stop; closing a browser tab alone does not stop the service.
  • Windows 10/11 x64, macOS 15+ Intel/Apple Silicon and glibc 2.35+ Linux x64 are the intended targets. Older OS versions, Alpine/musl, Linux ARM and Windows ARM are not validated targets.
  • One-file startup extracts bundled runtime assets to writable temporary storage. Linux noexec temporary directories require an executable TMPDIR.
  • The system browser and normal OS libraries remain prerequisites. Offline operation does not describe unrelated browser/OS network behavior.
  • No workspace UI/audio behavior was changed; interactive playback and old-OS compatibility were not newly certified by these packaged HTTP checks.
  • One existing FastAPI/Starlette TestClient deprecation warning remains in the local Python suite. It does not affect packaged runtime smoke checks.
  • No release tag was created; tagged release publication is configured for maintainers after review.
